## The restore drill, actually run

Not a simulation. On 2026-09-10, against PostgreSQL 17.10 and MinIO:

```
wrote /tmp/af-drill/backup.afbk (2857156 bytes), sealed with key id af-backup-drill
  schema:   0014_restore_reconciliation.sql
  evidence: 1095 object(s)

restored PostgreSQL into accessforge_drill
restored 1095 evidence object(s) into accessforge-drill-evidence
reconciled: revoked 3 sessions, expired 0 enrollment tokens, fenced 0 leases, quarantined 0 runners
and 0 ambiguous attempts, released 0 jobs and suppressed 0 undelivered messages.
```

Then the control plane was pointed at the restored database:

```
/health/ready -> 200  schema: at 0014_restore_reconciliation.sql
/v1/session   -> 401
```

That 401 is the module. The restored database is servable by the **application role** — because the
dump preserved ownership — and every session it brought back is gone, because reconciliation revoked
them. A restore that produced a 200 there would have handed back a live session that somebody may
have revoked an hour after the snapshot.

Four refusals were driven through the real command and all four fired: restoring over the source
(exit 2, compared by host/port/database rather than by string, so a different spelling of the same
database is still caught), restoring into a populated database (exit 2, **before** anything is
written), a truncated archive (exit 1), and the wrong key (exit 1).

## The decisions worth reading

**`pg_dump --no-owner --no-privileges` is the reflex and it is wrong here.** Tenant isolation is
expressed as table ownership plus `FORCE ROW LEVEL SECURITY`. A dump that discarded ownership
restores tables owned by whoever ran the restore, with no grants, and the application role can read
nothing. `test_a_dump_that_discards_ownership_produces_an_unusable_restore` asserts it.

**The backup role must bypass row-level security.** `FORCE` applies to the table owner, so `pg_dump`
run as the application role fails — it cannot read its own rows. This is an operational fact, so it
is a test (`test_the_application_role_cannot_take_a_backup`) rather than a line in a runbook.

**Reconciliation refuses a connection that cannot see every workspace.** An unscoped application
connection sees *zero* rows of every tenant table, so every `UPDATE` would report success and change
nothing — an operator following the runbook, seeing no error, and serving a database full of valid
credentials. `assert_can_reconcile` refuses anything without `rolsuper`/`rolbypassrls` rather than
running and doing nothing. This was found by writing the drill and watching reconciliation report
success while changing nothing.

**A restored lease says `RESTORED_DATABASE`, not `AMBIGUOUS_ACTION`.** Migration 0014 widens the
check constraint rather than reusing the closest existing value. `AMBIGUOUS_ACTION` is what an
operator searches when hunting a real unresolved action; putting every restored lease in that bucket
would make the two need different follow-up and look identical.

**The backup envelope is framed, not a single encrypted blob.** AES-256-GCM in 1 MiB chunks, with
the chunk index, a final-chunk flag and a per-archive `stream_id` bound into each chunk's AAD. Each
of truncation, reordering and cross-archive splicing is a test that performs the attack on a real
sealed archive. An empty payload still writes one chunk marked final, because "the backup was empty"
and "the backup was destroyed" must not be the same observation.

**Startup does not migrate, and readiness reports the result.** Two replicas booting together would
migrate concurrently, and a binary that migrated on boot would migrate *forward* again during a
rollback — turning a rollback into a second upgrade. `test_starting_against_an_unmigrated_database_does_not_migrate_it`
asserts the database is untouched after a full startup/shutdown cycle.

**Readiness reports the desktop runner as unknown, outside `dependencies`.** Everything inside that
object contributes to the verdict. Folding the runner in either way would be a lie: as a passing
check it claims a desktop exists, and as a failing one it makes a healthy control plane look broken.

**Trusted and untrusted CI are separate files.** `ci.yml` runs fork code, references no repository
secret, disables package lifecycle scripts, and cannot deploy. `release.yml` cannot be triggered by a
fork, refuses a tag that is not an ancestor of `main`, and *calls* `ci.yml` rather than copying it —
two copies of a pipeline diverge, and the copy that diverges is always the one nobody reads.

## What the tests found that I got wrong

Four defects, all found by writing the test rather than by reading the code.

1. **A killed worker does not leave a claimed job.** The first version of
   `test_a_worker_killed_...` asserted the job stayed `CLAIMED` and failed: `claim_jobs` leaves the
   transaction open for the caller to commit alongside the work, so an abrupt kill rolls the claim
   back entirely — attempt counter included. That is the right design and the test now says so. The
   window that *does* cost something (killed after committing the claim) is a separate test.
2. **Following `.env.example` made the API refuse to start.** `ApiSettings` uses `extra="forbid"`
   with the `ACCESSFORGE_` prefix, so the backup variables I added there produced two
   `extra_forbidden` errors from the file whose entire purpose is to be copied. Fixed by giving the
   backup operator their own `.env.backup.example`, and guarded by a test that checks every
   `ACCESSFORGE_` name in the example against the model's fields.
3. **The CI guards matched their own comments.** Both the "no repository secret" and "no
   `pull_request_target`" steps grepped the raw workflow file and failed against the prose warning
   about the thing they were checking for — the same defect class as module 23's structural CSS
   tests. They now strip comments and parse trigger keys with a YAML parser.
4. **A missing migration ledger reported `UndefinedTable`.** The most common unready state there is
   — an empty database between "it exists" and "the migrator has run" — got the least useful
   message, sending an operator looking for a bug instead of running the migrator.

Three CI guards and the `.env.example` guard were mutation-checked: each was broken deliberately,
observed to fail with a specific message, and restored byte-identically (SHA-256 verified).

## What is not done

- **Nothing has been deployed anywhere.** `infra/aws/` is a written proposal. It has never been
  applied, never been `terraform validate`d (no Terraform binary in this environment), and never
  touched an AWS API (no credentials). The IAM policies are shapes with placeholder ARNs.
- **No desktop runner is proposed for AWS.** No AWS service provides a real interactive desktop with
  a working screen reader. Whether an EC2 Mac can be driven under automation with the required
  Accessibility and Automation grants is **unverified here**, so it is not described as if it were
  solved.
- **Incremental backup is not implemented.** Every full backup copies every evidence object. For a
  large store this is expensive, and it is a known limitation rather than a solved problem.
- **No cost figures.** `RESOURCES-AND-COST-DRIVERS.md` contains no prices and no estimates for the
  four numbers the cost model turns on — desktop-seconds per run, tokens per run, requests per second
  per task, and storage growth — because none has been measured. No run has been executed against a
  real screen reader and no model has ever been invoked by this system.
- **No load test.** Every instance class in the proposal is a starting point, stated as such.
- **The doctor has no unit test.** It was run for real against this machine (and correctly caught the
  pending 0014 migration), but its verdict logic is not covered by a test. The data it reads *is*
  covered, by `test_version_matrix.py`.
- **`pnpm audit` is new and unproven in CI.** It has not yet run against a real advisory database in
  this pipeline; a first run that finds a high-severity advisory will fail the security job, which is
  the intent but has not been observed.
- **No independent review yet.** Everything above was written and reviewed by the same person.

**The acceptance gate is met for local and not for hosted.** A fresh environment runs the complete
declared local product path — verified in a real browser against the real API, real PostgreSQL and
real MinIO after this module's changes. An isolated restore preserves the authoritative state
without duplicating actions or claiming missing evidence — verified by a real drill. Hosted
deployment remains **PREPARED**.
