## Permissions and actual tested mode

The access probe requests only `metadata:read` and `contents:read` for one repository. Temporary
token issuance and revocation are remote mutations, so actual invocation needs explicit operator
authorization. No actual token was issued or App installed during this implementation.

Checks require a separately scoped `checks:write` installation token; comments, branches and PRs
need their endpoint-specific permission review before implementation. No standing publication
policy is implemented. Every GitHub write still requires an exact preview and GITHUB_PUBLISH
approval. Human ACCEPT, RUN_EFFECTS and PATCH_APPLY do not substitute for it.

Tested evidence consists of fixture HMAC cases, mocked GitHub HTTP, ephemeral local signing keys,
disposable PostgreSQL migrations/RLS/transactions and in-process receiver HTTP. It is not physical
reader qualification, actual GitHub App access, deployed credential isolation or publication proof.
CI success on the platform-reporting job only reports the blocked physical matrix; it is not AT PASS.
