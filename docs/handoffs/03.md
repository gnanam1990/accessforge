Every cell of the 6 × 10 grid is tested. The two producing sets are disjoint, asserted at import
time, and each event kind has exactly one permitted producer — two would mean no separation, none
would mean dead contract surface. Only a supervisor **holding a lease** may dispatch an
operating-system action; the observer is excluded even though it is a trusted component, because it
must not influence what it is verifying.

## Database isolation results

Row-level security with `FORCE` on `workspace_membership`, `enrollment_credential`, `runner_device`,
`environment_authorization` and `audit_event`. Tested by issuing SQL directly, with no API or
middleware involved:

| Attempt | Result |
|---|---|
| Scoped read of another workspace by id | 0 rows |
| `SELECT *` with no predicate at all | only the scoped workspace |
| Unscoped connection reading scoped tables | 0 rows |
| Malformed or unknown scope (`''`, `not-a-uuid`, nil UUID) | 0 rows |
| Insert directed at another workspace | `InsufficientPrivilege` |
| Update or delete targeting another workspace | 0 rows affected, other tenant unchanged |
| `relforcerowsecurity` on all five tables | true |
| `FORCE` removed inside a rolled-back transaction | **both workspaces leak** |

That last row is the self-test: it confirms these tests detect an absent policy rather than an empty
database. Without it, plain `ENABLE` would have made every isolation test pass while proving nothing,
because the application connects as the table owner in development.

## Secret-handling changes

Session, CSRF and enrollment tokens are stored as SHA-256 hashes; raw values exist only in the object
returned at issuance. A password hash would be the wrong tool — these are high-entropy random values,
so there is no guessing attack to slow down, and what matters is that the stored form is not a usable
credential.

`audit_event` has no column for a password, token, reader transcript or demographic attribute, so a
careless caller cannot write one. A test enumerates the actual columns to assert this rather than
trusting the schema comment. Denials are recorded alongside allowances: a denial that leaves no trace
is indistinguishable from a request nobody made.

## Deliberately not done

- **No HTTP routes.** Module 18 owns the API surface. Exposing authenticated endpoints here would
  duplicate its work and create a second authorization path to keep in step.
- **No separate restricted database role.** `FORCE` row-level security provides the equivalent
  enforcement testably; a distinct login role is defence in depth for module 26, where provisioning
  is in scope. Recorded in ADR 0004 rather than left implicit.
- **No identity-provider integration.** `issue_session` deliberately does not authenticate anyone;
  establishing who a user is belongs to the configured provider. The E0 owner-operated path creates
  test identities explicitly, with no default credentials and no implicit bootstrap.
