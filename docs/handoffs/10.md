# Handoff 10 — Provenance-bound evidence ingestion

- **Module:** 10 (depends on 04, 07; consumes 08/09 output when it exists)
- **Requirements:** FR-006, FR-014, FR-015, FR-020
- **Invariants:** INV-03, INV-06, INV-07, INV-11, INV-14, INV-15

## What this adds to module 04

Module 04 built the canonical chain: one trusted sequencer per attempt, producer source records,
closing watermarks, `admit_record`, `chain_is_contiguous`, `producer_tails_closed`. None of that is
re-implemented here.

Module 10 adds the half that turns an ordered chain into an **evidence set**:

| Piece | Where |
|---|---|
| Object store, key construction, size and content-type policy | `evidence/objectstore.py` |
| Quarantine, server-side hashing, promotion, redaction, retention | `evidence/artifacts.py` |
| Finalization prerequisites, late arrivals, bounded ingest, replay | `evidence/finalization.py` |
| `evidence_artifact`, `required_artifact`, `rejected_arrival` | migration `0009` |

## The object store is real

MinIO under Colima locally; a MinIO container in CI. **There is no filesystem fallback**, and the
artifact fixture calls `pytest.fail` rather than `pytest.skip` when the endpoint is absent — a skipped
artifact suite on a machine with no store looks like a passing build, which is exactly the shape
SESSION-HEADER §12 forbids.

A fake store would have passed every assertion about size limits and content types while proving none
of what only a real store does. The clearest example is `test_promotion_re_reads_the_bytes_and_catches_a_swapped_object`:
the object is replaced in the bucket between upload and promotion, and without the re-read the row
keeps its original digest and the artifact becomes trusted evidence carrying a hash of bytes that are
no longer there. That case cannot be constructed without a store to swap the object in.

## Three things that are true of every artifact

**The digest is the server's.** `upload_to_quarantine` has no parameter through which a caller could
declare one — a test asserts that over the signature, not by spot-check. An uploader able to name the
hash of its own upload can name the hash of bytes it did not send, and every later integrity check
would then confirm the declaration rather than the content.

**Keys are constructed, never accepted.** `artifact_key` builds the key from validated uuids, the kind
and the digest. There is no caller-supplied key, so there is no `../../other-tenant/transcript.txt`,
no absolute path and no embedded newline. Validating a caller-supplied key would mean enumerating
every way a path can escape a prefix, which is the losing side of that problem. The digest is part of
the key, so the store is content-addressed: identical bytes write the same object and different bytes
cannot overwrite an existing artifact by reusing its name.

**Nothing is promoted on arrival.** Quarantine → server-side hash → re-read and re-hash → manifest
binding → promotion. CONTRACTS section 7 in one pipeline: no artifact becomes trusted because its JSON
says PASS.

The content-type allowlist deserves its own sentence, because it looks like bureaucracy and is not: a
stored HTML or SVG "transcript" **executes when someone opens it from an export**. That is a stored
cross-site scripting payload with a chain of custody. `ContentDisposition: attachment` is set on every
upload as defence in depth behind it, not instead of it.

## Contiguity is not completeness

The assertion this module exists to make executable, and the one most likely to be got wrong:

> A contiguous canonical chain is not a complete evidence set. The sequencer assigns consecutive
> positions to whatever it admits, so a producer that stopped halfway leaves a **perfect** chain and
> half the evidence.

`test_a_contiguous_chain_with_an_unclosed_producer_is_incomplete` asserts `chain_contiguous is True`
and `complete is False` in the same test, so the two cannot be conflated by a later reader. Contiguity
and closing watermarks are separate checks and both are required (INV-06).

A required producer with **no stream row at all** counts as unclosed, not as absent-and-therefore-fine.
Absence is not completion: a producer that never spoke is indistinguishable from one whose records
were all lost.

## Completeness cannot express an outcome

`assess_completeness` returns reasons. `Completeness` has no `outcome`, `verdict`, `passed`, `result`
or `status` field, and a structural test asserts it never gains one. A completeness checker that
guessed at outcomes would be a second place where PASS could be decided, and the architecture depends
on there being exactly one — module 11's.

Every failing check runs and every failure is reported. Short-circuiting would make an operator fix
one thing, re-run, and discover the next; the prompt asks for "invalid/incomplete reasons", plural.

## Retention: the record outlives the bytes

INV-15 says a deletion must not leave an export that still looks fully verifiable. The way that goes
wrong is deleting the row — the export then has no idea the artifact ever existed and reports a
complete evidence set for a run whose evidence is gone.

So `delete_artifact_bytes` deletes the objects and **keeps the row**, setting `retention = 'DELETED'`
with a timestamp and a reason. `missing_required_artifacts` counts a DELETED required artifact as
missing, with reason `BYTES_DELETED` distinguished from `NEVER_UPLOADED` and `STATE_QUARANTINED` —
three ways to be missing that send an operator somewhere different.

A redacted view is a **separate object with its own digest**, not a flag. One digest describing two
byte streams would make later verification check the wrong one, and an export citing "the transcript"
would be ambiguous about which it meant. A redaction that produces byte-identical content is refused:
recording it would claim a redaction that did not happen.

## A late RUN_FINISHED cannot resurrect an interrupted run

`assert_run_accepts_evidence` refuses evidence for a terminal run and **records the refusal**. The
failure it prevents is quiet: a supervisor partitioned during an interruption reconnects, sends its
buffered tail, and the run's evidence set silently gains records from after it was declared over
(INV-11).

`rejected_arrival` deliberately has **no payload column**, asserted both over the function signature
and over `information_schema`. A rejected record may carry a transcript, a form value or a token, and
storing it "so we can look at it later" moves unvalidated content from an unauthenticated source into
the audit trail. The digest is enough to correlate it with a producer's own logs.

## Backpressure refuses the new arrival, never evicts the old

An unbounded staging buffer is a memory-exhaustion channel: a producer that sends sequence 2, 3, 4 …
and never sends 1 stages every one of them. At the limit the **new** arrival is refused and recorded.
Evicting something already staged would discard evidence that has already been accepted, and the
prompt forbids exactly that — exhaustion "cannot discard required evidence while preserving a green
result".

## Replay pagination, and a semantics worth stating

Keyset pagination on the canonical sequence, not OFFSET. The chain is append-only, so a keyset cursor
is stable under concurrent ingestion; an OFFSET page silently skips or repeats records as the chain
grows underneath a reader, and a replay that quietly omits an event is the one thing a replay must
never do.

`exhausted` is true only for a **short** page. A page that is exactly full never sets it, even when it
happens to be the last, because the query cannot distinguish "four events exist" from "four events
exist so far". The test fetches a third, empty page to confirm the end. The first version of that test
assumed a full final page would report exhaustion — reporting it would stop a reader one page early
whenever the total is a multiple of the page size.

## Summaries carry no content

`evidence_summary` returns counts, producer identities, artifact kinds and digests. No object keys, no
transcript text. A summary is the thing most likely to be rendered somewhere unexpected, and an object
key in a summary is a step towards an object key in a log. A test asserts neither appears.

## What this does not establish

**No real screen-reader output has passed through this pipeline.** Modules 08 and 09 are blocked, so
every producer record in these tests was constructed by the test. The ingestion, integrity and
completeness logic is exercised adversarially; the claim that it correctly ingests *actual VoiceOver
output* is unproven and stays unproven until module 08 can run.

The prompt's stop condition — "missing actual producer evidence limits integration status" — applies:
integration status is **contract-verified, not end-to-end verified**.

`Integrity attests authenticated ingestion, not physical truth.` A promoted artifact with a matching
digest means the bytes we hold are the bytes that were sent by an authenticated producer. It does not
mean a screen reader said what the transcript claims.
