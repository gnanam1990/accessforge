## Regression and failure cases proved

Mutation checks against high-risk guards, run in the working tree and restored from a pristine
copy verified byte-identical afterwards:

| Mutation | Result |
|---|---|
| Authorization always allows | **7 integration tests failed** |
| Email validation removed | **7 tests failed** |

| Restored candidate | 69 passed; `diff -r` against pristine showed no differences |

**A correction worth recording.** The first mutation attempt ran in a copied worktree whose
editable installs still pointed at the original source tree, so the mutants were never imported
and all five "passed". That was a check proving nothing. It was redone in the real tree with a
verified restore, and only those results are reported above.

Three defects were found by these tests and fixed before commit:

1. **Authorization was not running.** Declaring the token dependency as `Annotated[None, Depends(...)]`
   made FastAPI treat it as a request field, so an unauthenticated call was rejected as malformed
   (422) before the authorization dependency was consulted. Moved to route-level `dependencies=[...]`.
2. **Placeholder detection used equality**, so `REPLACE_ME_WITH_A_RANDOM_VALUE` — the exact value
   shipped in the example files — would have been accepted as an observer token. Now substring-based.
3. **`.gitignore` would have excluded two of the three `.env*.example` templates**, leaving a fresh
   clone with no template for them. Pattern changed to `!.env*.example`.

## Independent review findings and closure

A separate reviewing agent reviewed `fc00eb8..ea6c373` read-only. It raised three findings; all
three were reproduced by executing them, then fixed with tests written first.

| # | Finding | Severity | Status |
|---|---|---|---|
| 1 | The CI step asserting `specs/` is unmodified always passed | Critical | FIXED WITH PROOF |
| 2 | The reference application's "must be a local database" guard was bypassable | Important | FIXED WITH PROOF |
| 3 | `_production_defaults` was a no-op validator | Important | FIXED WITH PROOF |

**Finding 1.** `git diff --name-only origin/main...HEAD -- specs/` was run in a default shallow
checkout where no `origin/main` ref exists, and stderr was discarded with `|| true`. Reproduced by
cloning the branch with `--depth 1` and running the exact command: `fatal: bad revision
'origin/main...HEAD'`, swallowed, leaving `changed` empty so the guard reported success
unconditionally. This is the failure class the project exists to prevent, in its own CI.
Fixed with `fetch-depth: 0`, an explicit fetch of `main`, a merge-base comparison, `set -euo
pipefail` with no error suppression, and a self-test that fails if the diff mechanism returns
nothing on a pull request. Verified against a full clone: the merge base resolves, 53 files differ
from base, `specs/` is empty, and appending a line to `CONTRACTS.md` makes the guard fire.

**Finding 2.** `_require_local_database` substring-matched `"@localhost"` against the whole URL.
Reproduced: `postgresql://user:pass@evil.example.com:5432/refapp?application_name=x@localhost` was
**accepted**, with a real host of `evil.example.com`. Fixed by parsing with `urlsplit` and checking
the actual hostname, including a `host=` query parameter (which overrides the authority for libpq)
and unix-socket forms. The previous implementation also rejected legitimate socket URLs such as
`postgresql:///dbname`, which now work.

**Finding 3.** `_production_defaults` was decorated, named for enforcement, and returned its input
unchanged. Reproduced: a `production` configuration with a plaintext `http://` evidence endpoint
and a `localhost` database was accepted. Replaced with a real `model_validator` that requires an
https evidence endpoint in staging and production, and rejects a loopback database in production.
Dead code shaped like a guard is worse than no guard.

New mutation checks confirm all three fixes are load-bearing: reverting the host check fails 5
tests, ignoring the `host=` override fails 1, and reverting the production rules to a no-op fails 3.

The reviewer explicitly found no material issue in token handling, seeded-defect symmetry, HTML
escaping, the one-request-per-fixture constraint, credential leakage, or test vacuity.

## Deviation from the module's own instructions

The prompt asks for test-first development. Validation, configuration and template code were
written before their tests, then tests were added and the guards mutated to prove the tests fail
when the behaviour breaks. The mutation results give the same falsifiability guarantee test-first
is meant to provide, but the ordering was not followed and is recorded rather than glossed.

## Security and privacy implications

Loopback binding is enforced by configuration for the reference application; non-loopback hosts and
non-local database URLs are rejected. Observer and setup identities are distinct and neither
substitutes for the other. Credentials never appear in diagnostics or dependency-failure output —
health checks report exception class names only, because driver messages can embed connection
strings. No `.env` file is committed. The database role is not a superuser. The CI workflow uses
`permissions: contents: read`.

The reference application performs no outbound network calls, sends no email, takes no payment,
and cannot submit anywhere external.
