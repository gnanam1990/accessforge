# Handoff 08 — macOS VoiceOver adapter

- **Module:** 08 (depends on 00 and 07)
- **Requirements:** FR-004, FR-005, FR-006, FR-015
- **Real-reader capability for E0: BLOCKED.** Not partially, not degraded — no VoiceOver observation
  has ever been produced by this code.

## The answer the prompt asks for

> "Identify whether E0's real-reader capability is proven or blocked."

**Blocked.** VoiceOver has never been run on this host: there is no preferences file at either the
legacy path (`~/Library/Preferences/com.apple.VoiceOver4/`) or the macOS Sequoia+ sandboxed path
(`~/Library/Group Containers/group.com.apple.VoiceOver/…`). Beyond that, three things are required and
none of them can be done by software:

| Required | Why software cannot do it |
|---|---|
| "Allow VoiceOver to be controlled with AppleScript" (VoiceOver Utility → General) | A VoiceOver security setting |
| Accessibility permission for the controlling process | A TCC grant; a process that could grant itself the right to read the screen would be doing the most invasive thing in this system as a side effect of a health check |
| Automation permission for the controlling process | As above, for driving other applications |
| A dedicated signed-in desktop session | Module 07 fences a desktop on any ambiguity and will interrupt whatever is on that screen |

Every E0 acceptance criterion that requires an actual reader is therefore unmet, and this handoff does
not soften that anywhere.

## The navigator channel is a construction, not a filter

`projectForNavigator` reads two fields off a raw observation and returns a new object with three. It
does not take the rich object and delete the dangerous keys.

The difference decides what happens when someone adds a field upstream. A filter includes new fields
by default and depends on the next author remembering this file exists. A construction excludes them
by default, and getting something to the navigator requires an edit here, in a file whose tests are
about exactly that. A test adds a field to a raw observation and asserts it does not appear.

Bounded length is part of the same boundary: an unbounded announcement is a channel, and a page that
rendered its own source into an ARIA label could hand the navigator the DOM through the one route
that is supposed to be safe.

## A capture timeout is not silence

`captureTimedOut` returns an object with no `phrase` field at all, rather than an empty string.

An empty announcement is a real and sometimes correct observation — an unlabelled control genuinely
announces nothing. A timeout means we do not know what was said. Collapsing the second into the first
manufactures an observation, and module 11 evaluates a missing required announcement as FALSE rather
than UNKNOWN, which turns an infrastructure gap into a reported accessibility defect (INV-02).

## The chord allowlist is an enumeration, not a denylist

`ALLOWED_CHORDS` lists seven chords: `TAB`, `SHIFT+TAB`, `ENTER`, `SPACE`, `ESCAPE`, and VoiceOver's
own `CTRL+OPT+LEFT`/`CTRL+OPT+RIGHT`. Anything else is refused whether or not anyone anticipated it.

A denylist would be wrong by construction: it has to anticipate every dangerous shortcut in an
operating system nobody controls, and it fails open on the one nobody thought of. `EXPLAINED_REFUSALS`
exists only so that a navigator reaching for developer tools is told *why* that is not an
accessibility action — it is not the mechanism, and a test asserts no entry in it is also allowed.

A property test asserts no allowed chord carries `CMD`, the macOS application and system modifier.

**Ordering:** `dispatch` validates the action *before* checking reader availability, so a forbidden
chord is refused as a policy breach rather than as "no reader available". Those are different findings
— one is about the navigator, one is about the host — and a reviewer reading the trace needs to see
which happened.

## Preflight never enables anything, and never defaults to TRUE

Every probe reads and reports. A missing permission is an explicit FALSE carrying the System Settings
path and the sentence "This software does not grant it".

A test asserts that on a bare host exactly one check is TRUE — `MONOTONIC_CLOCK_HEALTHY`, the only one
that genuinely needs no reader. That test exists because the easy placeholder for an unimplemented
probe is the passing value, and a preflight that passes on a machine where nothing was checked is
worse than no preflight.

`hostEnvironment()` performs read-only macOS, Safari, console-session and TCC probes. The remaining
setup-owned checks stay UNKNOWN until the supervisor supplies concrete reset, origin, build, stale
input, journal and speech-capture observations. `undefined` becomes UNKNOWN, and module 07 fails
readiness on UNKNOWN.

## The shortcut this package is shaped to refuse

`@guidepup/virtual-screen-reader` runs anywhere and produces plausible announcements. Using it would
have made this module look finished. It would also have produced a system that reports accessibility
results for a screen reader nobody uses — which is the specific failure this product exists to prevent.
The prompt permits it in labelled unit tests only; this package does not depend on it at all, and a
test reads `package.json` and asserts so.
