## What is built

The orchestrator now constructs an actual `strands.Agent` backed by an explicit
`strands.models.BedrockModel`. Construction is not counted as a model invocation. Every planning
turn creates a fresh agent and supplies exactly one explicit tool,
`submit_navigation_action`; `load_tools_from_directory` is false, context management is disabled,
and there is no session manager, memory manager, background task, SDK checkpoint store or generic
shell/browser/repository/HTTP tool.

## Enforced boundary

`NavigatorProjection` constructs a new closed model from approved task intent, safe fixture-value
names and actual-reader observations. Pydantic uses `extra="forbid"` throughout. Whole-policy
validation fails if an upstream caller adds a selector, observer token or another privileged field;
it is not a filter that silently copies future fields. `CAPTURE_UNKNOWN` cannot carry a manufactured
phrase and `ACTUAL_READER` must carry the observed phrase, including genuine silence as `""`.

The only proposed actions are `NEXT`, `PREVIOUS`, `ACTIVATE`, `TYPE_TEXT`, `KEY_CHORD`,
`READ_CURRENT`, `WAIT_FOR_READER_IDLE` and `STOP`. `TYPE_TEXT` carries a sealed fixture reference,
not raw text. The gateway resolves it only after schema validation and re-reads lease epoch,
cancellation, in-flight action, action budget, wall-time budget and current origin before each
supervisor dispatch. An invocation-local claim admits at most one proposal even if a model response
contains several tool uses; another action requires a fresh reader projection. The supervisor
remains the final authority and atomically journals intent before an OS effect.

Prompt instructions are defense in depth only. A forged selector action, shell field, observer
receipt, unknown field, raw text or `CMD+L` is rejected by schema or gate below the prompt.
Announcements that say to reveal secrets or call shell remain quoted data and cannot change the
tool inventory or policy.

## Budgets, interruption and ambiguous effects

- Provider output is capped at 512 tokens per call.
- One SDK invocation is capped at 1 turn, 1,024 output tokens and 12,000 total tokens. A dispatch
  result cannot trigger another model decision; the caller must retain a fresh actual-reader
  observation and create the next bounded invocation.
- Serialized projection context is capped at 24,000 characters.
- The provider wall-clock timeout is 30 seconds.
- Only Bedrock throttling is retried, with at most 2 attempts and bounded 1–2 second delay.
- Desktop effects are never automatically retried. Transport uncertainty or a post-dispatch
  planning-checkpoint failure returns `AMBIGUOUS` and closes the invocation fence.
- An expired lease, changed epoch, cancellation, in-flight effect or exhausted action/wall budget
  refuses dispatch visibly.

The model chat is not durable state and is never used to resume a terminal attempt. Continuing after
interruption requires the control plane to create a linked run, reset the fixture and re-authorize
before supplying a new projection.

## Checkpoint retention

Migration `0019_navigator_planning_checkpoints.sql` adds a FORCE-RLS, workspace-scoped PostgreSQL
table. It retains model identity, stop reason, proposed action name, safe argument reference and
dispatch status. Its schema has no columns for reader announcement content, resolved fixture text,
DOM, source, screenshot, observer receipt or assertion expectation.

`PostgresPlanningCheckpointSink` commits each checkpoint in a separate workspace-scoped transaction
before returning. Proposal retention is fail-closed before dispatch. The supervisor's action journal
remains the authoritative effect record.

Local database verification used a disposable PostgreSQL 17 container: four previous-to-current
migration drills and two navigator-checkpoint integration tests passed; two checkpoints were
committed and read back through the workspace scope, while a different workspace saw no rows. The
disposable container was removed afterwards.
