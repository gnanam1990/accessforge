# Handoff 11 — Independent deterministic outcome verifier

- **Module:** 11 (depends on 06 and 10)
- **Requirements:** FR-006, FR-007, FR-011, FR-023
- **Invariants:** INV-01 through INV-06, INV-11, INV-12, INV-16

## What a PASS from this verifier establishes

Attached to every verdict as `PASS_SCOPE_STATEMENT`, not kept in documentation, because a verdict
travels into exports and dashboards and the caveat has to travel with it:

> This result describes one journey, executed once, on one pinned reader, browser, locale and
> keyboard layout, against one build of one environment. It establishes that the frozen assertions
> held for that execution. It does **not** establish that the application is usable by people with
> disabilities in general, that it works with other assistive technologies or other versions of this
> one, that untested journeys behave the same way, or that any legal or regulatory obligation is
> satisfied. Actual screen-reader automation supplements evaluation by disabled users and
> specialists; it does not replace it.

## Where the truth table lives, and what this module adds

Module 02 owns the precedence. This module owns everything around it:

| Piece | File |
|---|---|
| Identity revalidation, before anything else | `evaluation/identity.py` |
| Assertion values with provenance and evidence references | `evaluation/assertions.py` |
| The independent completion observer | `evaluation/observer.py` (protocol), `persistence/evidence/observer.py` (real) |
| Verdict assembly, scope, finding support | `evaluation/verdict.py` |

## Identity before observations

`revalidate` runs first and feeds `EvidenceValidity`, so a mismatch never reaches the truth table.
An evaluator that checked identities afterwards would compute a verdict and then decide whether to
believe it, and the natural failure of that shape is a plausible result reported against the wrong
build. A test asserts the ordering directly: every assertion TRUE, one identity changed, INCONCLUSIVE.

Every identity in `ALWAYS_REQUIRED` is parametrised — eight changed-identity tests and eight
missing-identity tests — rather than the two or three an author would have remembered.

Three failures are kept distinct because they lead somewhere different: **never sealed** (nothing was
promised), **not reported** (the promise cannot be checked), **different** (the promise was broken).
Collapsing them into "identity mismatch" sends someone to compare two digests when one was never
recorded.

`MODEL` is optional but not ignorable. A scripted navigator legitimately has none; a run reporting a
*different* model than the one sealed is not the approved run, and accepting it silently is how a
substitution lands.

## Provenance travels with every value

The evaluator **may** derive a reader assertion from a retained transcript — that transcript is the
reader's own evidence, and CONTRACTS section 7 permits it. The evaluator **may not** derive an
application observation, because no retained artifact implies "the backend received exactly one
request"; a derived value there is the evaluator inventing a backend observation and presenting it as
one. `assert_provenance_permitted` refuses the second, and the test covers the whole assertion
vocabulary rather than the single case the prompt names.

Three constructor guards make a value unusable if it is not reviewable:

- an **absent** observation must be UNKNOWN — reading it as FALSE turns a capture failure into a
  reported accessibility defect (INV-02);
- a definite value needs an **evidence reference** — a FALSE nobody can trace is not reviewable;
- an UNKNOWN needs a **reason** — "we do not know" is only useful to a reader told what was not known.

An assertion with no submitted value stays in the required set as UNKNOWN rather than being dropped.
Dropping it would shorten the list of conditions a PASS has to satisfy, which is exactly the direction
a repair must not be able to push the evaluation (INV-16).

## Completion is measured, not read

The observer counts rows the application actually holds, keyed on this run's fixture nonce. It reads
the application's own database — not an HTTP endpoint it serves, because an endpoint returns what the
application chooses to say, and not the DOM, because the DOM is what the page chose to display.

The integration test executes the failure this exists to prevent: nothing is submitted, and the
observation is FALSE. In a real run of the inaccessible variant every reader assertion would be
correctly TRUE, because the page renders a success message having persisted nothing.

**Read-only at the database.** `SET TRANSACTION READ ONLY`, so an attempted write fails rather than
relying on this class not containing one. The realistic way an observer gains a write is someone
adding a `reset_fixture` helper to it — it already holds a connection to the application and it looks
tidy — and a read-only transaction makes that attempt fail instead of succeed. A structural test
asserts the class exposes exactly one public method.

**Unavailability is UNKNOWN, never zero.** A connection refused and "the application holds no
requests" are opposite conclusions; returning zero would report a confirmed task failure every time
the network hiccuped.

**A prior fixture's receipt does not count.** Effects are counted per nonce. Without that, one
successful run would satisfy every later run's completion assertion for as long as the row survived.

**The observation carries no oracle material.** `CompletionObservation` has no `expected` field, so a
caller holding one cannot read what the count was compared against.

## A property of the reference application, found by trying to test around it

The first version of the double-submission test inserted two rows to check that two reads as FALSE.
It could not: the reference application holds a unique index on `fixture_nonce`, so a second
submission for one fixture is refused by its own database.

That is asserted now rather than worked around. The observer's *exactly one* comparison is a check on
a count the application cannot make exceed one — so a run reporting two would be evidence of something
much stranger than a double click. The comparison stays, because an observer that only checked "at
least one" would accept a state the application considers impossible without anyone noticing.

## Findings

Only a complete, valid FAIL supports `REPRODUCED`. An INCONCLUSIVE run containing a FALSE observation
supports `CANDIDATE` and nothing stronger: incomplete evidence cannot distinguish a real failure from
a consequence of what was missing. A PASS supports nothing — there is no such thing as a finding that
something worked.

## Test fixtures are independent of the code under test

The prompt asks for "independent offline/unit test fixtures not generated by the same code path as
evaluation", and the reason is that a fixture built by calling the thing under test agrees with it by
construction. The identity table, the assertions and the observer stubs in `test_outcome_verifier.py`
are all written out by hand.

## What this does not establish

**No real screen-reader trace has been evaluated.** The prompt's acceptance criterion — "real
VoiceOver trace evaluation yields explainable results" — is **unmet**, and cannot be met until module
08 is unblocked. Every reader assertion value in these tests was written by the test.

What *is* proved end-to-end is the completion observer: it reads a real PostgreSQL database belonging
to the real reference application, and correctly reports FALSE for a submission that did not happen.
That is the half of the verdict that does not require a screen reader, and it is the half that catches
the most dangerous failure — a page that announces success having done nothing.

## A CI gap the independence assertion exposed

The first CI run of this module failed on nine errors: `REFAPP_DATABASE_URL is not configured`.

Locally the reference application has its own database (`accessforge_refapp`); in CI it had been
sharing the product's. The existing reference-app journey test never noticed, because it passes the
product's URL to the application's settings and both work.

Sharing would have made `test_the_observer_reads_the_application_not_the_product` vacuous — it would
be comparing a URL to itself. It is also the arrangement that produced module 06's silent table
collision, where the product's `fixture_instance` was the name the application already used in the
same database. CI now creates `accessforge_refapp` owned by the non-superuser test role, so the two
sources are genuinely different.
