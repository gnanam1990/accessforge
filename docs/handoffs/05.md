## Immutable example manifest

A sealed manifest binds these separately, each a fixed-width hex digest enforced by a CHECK:

```
sourceCommitSha           40-hex git commit, resolved from the requested ref immediately
sourceTreeDigest          64-hex over path + content + symlink targets
buildArtifactDigest       64-hex, separate from source so substitution is visible
environmentConfigDigest   64-hex over origins, reset strategy, credential REFERENCES, effects
journeyDigest             assertionSetDigest   fixtureDigest
runnerProfileDigest       navigatorPolicyDigest
evaluatorVersion          modelConfigDigest
manifestDigest            64-hex over all of the above
```

## Threat tests

| Attack | Result |
|---|---|
| Force-pushed branch between sealing and dispatch | `IdentityChanged` — commit differs |
| Edited working tree, same commit | `IdentityChanged` — tree digest differs |
| Artifact substitution under the same URL | `IdentityChanged` — artifact digest differs |
| Environment revoked after approval | refused at dispatch, even when every byte matches |
| Dirty checkout presented as reproducible | `ReproducibilityRefused`, naming the paths |
| Untracked file | counts as dirty — it changes what a run sees |
| Rename with identical content | different tree digest |
| Symlink to a file outside the tree | recorded by target, not followed; target edits do not change the digest |
| Archive with an absolute path | refused |
| Archive with `../` traversal | refused, and nothing is written outside the destination |
| Archive with a symlink or hard link | refused — a link can be followed by a later member |
| Archive with a device node | refused |
| Case or default-port variation on an allowlist | normalized, so it cannot evade |
| Parent domain, subdomain, suffix trick | all refused — membership is exact |
| Embedded credentials in a URL | refused rather than stripped |
| Redirect to production | refused — a redirect cannot broaden authority |
| Redirect to cloud metadata | refused |
| Cross-workspace project reference | composite foreign key refuses it |
| Sealed manifest mutation | trigger refuses; a changed input needs a new seal |

## Credential separation evidence

- Observer and reset credential **references** must differ. One identity that can both reset state
  and attest to it is not an independent observer, so registration refuses it.
- Manifests store references only. No secret value reaches a manifest, a digest, or anything derived
  from one.
- References *are* in the config digest, deliberately: swapping which credential profile is used is a
  configuration change that should invalidate a seal.
- `capability_summary` exposes neither values nor references — a journey author needs to know a reset
  strategy exists, not which credential performs it. Asserted by a test.

## A constraint that was wrong, and a latent defect in module 04

**`manifest_digest UNIQUE` was wrong.** The first test sealing identical inputs twice failed on a
duplicate key, and the failure was correct: CONTRACTS section 4 says repeated execution creates a new
runId "even when source/journey are unchanged". Worse, the constraint would have forbidden the
comparison INV-04 depends on — a baseline and its candidate must differ only by an approved patch, and
comparing input digests is exactly how that is shown. Migration `0006` drops it and makes `run_id`
unique instead: one run has one seal, two runs may share inputs.

**A timestamp formatting defect in merged module 04.** PostgreSQL returns `timestamptz` in the session
timezone, and the formatter was `isoformat().replace("+00:00", "Z")` — producing
`2026-09-11T05:00:00-07:00` locally, which every parser here refuses. Module 04's reviewer raised this
as an unexecuted hypothesis rated low suspicion; it was real. It hid because no test reloaded a
cancellation timestamp and then compared it — `cancel()` refused earlier for a different reason.
Centralised in `to_rfc3339_utc`, with two regression tests doing the full request → reload →
acknowledge → reload → cancel cycle across separate transactions.

**A self-inflicted mess worth recording.** I tried to fix long lines with a script that did not
understand Python, and it split string literals and section banners across lines. Caught immediately
by the syntax check, repaired, and the audit confirmed no already-committed file was altered beyond
the intended changes. Line wrapping is not a job for a regex.
