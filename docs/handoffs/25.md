# Module 25 — fault laboratory and quality reporting

Status: **PARTIAL implementation, no actual benchmark acceptance**.
This checkpoint delivers denominator accounting for P-25 task 9 / T-076.
It does not execute the mandatory fault laboratory or qualify a reader/model.
The current model target is Codex; historical Strands/AWS wording is not a new
provider instruction.

## Delivered reporting command

```sh
uv run python scripts/benchmark_report.py \
  --plan /private/operator/benchmark-plan.json \
  --results /private/operator/benchmark-results.json
```

The command reads bounded JSON inputs and prints a JSON report. It starts no
service, reader, model, browser or mutation process. Invalid inputs produce a
generic diagnostic without echoing private data. Keep the operator-owned plan,
answer keys and report outside both navigator access and the patchable source
tree. Freeze and independently retain the plan before execution.

The plan has exactly these fields:

- `corpusVersion`: bounded version identifier.
- `identity`: `sourceCommit` (40 lowercase hex), `buildDigest`,
  `profileDigest`, `evaluatorDigest`, `lockfileDigest` (64 lowercase hex),
  `evidenceClass`, and a nonempty `versions` mapping of bounded identifiers.
- `cases`: unique `caseId`, `category`, `repetitions` (1–100), and
  independently protected `oracleDigest` (64 lowercase hex).

Categories are CLEAN, INJECTED_DEFECT, EXTERNAL_DEFECT, UNSUPPORTED and
INFRA_FAILURE. Evidence classes are UNIT, CONTRACT, LOCAL_INTEGRATION,
ACTUAL_AT, ACTUAL_MODEL, HUMAN_REVIEW and OPERATIONS. Each report uses one
exact identity/class cohort; produce separate reports for different proof
levels and platforms. Combining reports does not prove combined acceptance.

The results object has only `observations`. Each observation includes its
`caseId`, `repetition`, matching full `identity` and `status`.
COMPLETED requires `outcome` (PASS/FAIL/INCONCLUSIVE), `bundleDigest` and
`durationMs`. BLOCKED/TIMED_OUT require `reasonCode` and no verdict.
Optional fields are `bundleDigest`, `durationMs` and `reasonCode` as
appropriate. Never put secrets or free-form transcripts in these inputs.

Every planned repetition appears in output, including inferred NOT_RUN rows.
Duplicate slots, reused bundle digests, unplanned cases, excess repetitions,
mixed identities, nonfinite durations and unknown fields are refused. All five
categories appear, including zero denominators. Reports retain supplied
failures and separate false defects on clean controls, false passes on known
defects, unsupported conclusive verdicts, timeouts and inconclusive outcomes.
No global accuracy percentage is calculated.

## Trust boundary

The output kind is DECLARED_BENCHMARK_ACCOUNTING_NOT_EVIDENCE_VERIFICATION;
`evidenceVerified` is always false. A supplied bundle digest is a reference,
not proof of its contents, signature, provenance or independent execution.
Distinct digests do not prove independent repetitions. Oracle labels, exact
versions and pre-execution freezing require separate independent evidence.
The plan digest hashes normalized sorted-key JSON for inventory purposes; it
is not an RFC8785 run-manifest digest, signature or qualification attestation.

## Retained evidence inspection

The companion command adds offline findings without changing declared counts:

```sh
uv run python scripts/benchmark_evidence.py \
  --plan /private/operator/benchmark-plan.json \
  --results /private/operator/benchmark-results.json \
  --bundles /private/operator/retained-bundles \
  --trust-root /private/operator/issuer-public-key.json
```

Store each retained archive as `<SHA256-of-entire-ZIP>.zip`, matching the result's
`bundleDigest` (not its internal manifest digest). The optional, independently
obtained trust-root JSON has exactly `keyId`, `issuer` and `publicKey` strings;
the public key uses the existing verifier's Ed25519 base64 format. Never obtain
the trust root from the bundle being checked. No private signing key is needed.

This POSIX operator command opens a bounded regular file without following its
final symlink, hashes and copies it once into a private temporary directory,
then verifies that same snapshot. Snapshots are removed on exit. Nothing is
extracted, executed, uploaded or fetched. Allow temporary disk capacity for one
bundle, up to the existing 256 MiB archive limit. Keep the input directory under
operator control and outside navigator/repair access.

Each planned row retains its counts and gains `retainedEvidence`: NO_REFERENCE,
MISSING, UNREADABLE, DIGEST_MISMATCH, INVALID_BUNDLE or INSPECTED. INSPECTED means
checks ran, **not** that they passed. Read `integrityIntact`, the separate finding
counts (including UNSUPPORTED), `signatureMatches`, `independentTrustRoot`,
`signatureVerifiedWithIndependentKey` and `declaredOutcomeMatchesManifest`.
A wrong key can be independently supplied while its signature check fails.
The declared outcome must match both manifest and readable outcome; their
evaluator versions must also agree. Diagnostic output excludes raw bundle text,
paths and producer names. Run `accessforge-verify` privately on the retained ZIP
for detailed findings.

Exit 0 means an inventory report was produced, not acceptance or all evidence
passed; invalid operator inputs exit 2. Unusable bundle rows remain in the
report, not silently discarded. The top-level `evidenceVerified` stays false.
Source/build/profile/evaluator cohort mapping, evidence class, durations,
oracle labels, true independent repetitions and actual human/reader acceptance
remain unverified. This is retained-byte/signature inspection, not full T-076.

Ten synthetic inspection cases plus the sixteen accounting cases pass locally,
with scoped Ruff and strict mypy. Coverage includes missing/changed/unsafe
references, absent/wrong trust roots, signed/readable verdict disagreement,
malformed documents, size bounds and replacement after hashing. These fixtures
do not count toward actual benchmark coverage.
